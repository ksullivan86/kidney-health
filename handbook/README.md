# Kidney Health Handbook (`/learn`)

Practical, sourced guidance for people living with chronic kidney disease (CKD) and type 1 diabetes,
and for their families: what each stage means day to day, what to eat (with real numbers and
portions), how to read lab results, how to treat a low, what to do on sick days, and when to get help.
The app serves the built site at `/learn/`; a public copy can be published to GitHub Pages.

* **Spec:** `docs/dev/research/08-handbook-site.md` (tooling §4, editorial policy §4.9, content plan
  §5, bibliography §5.13). **Contract:** `ARCHITECTURE.md`, v0.3 items 11 (licence, draft banner) and
  12 (`/learn/...` links).
* **Status:** every page is a **draft**. No page has been signed off by a clinician yet. Open clinical
  questions are listed at the top of [`REVIEW.md`](REVIEW.md).
* **Licence of the text:** CC BY-NC-SA 4.0 ([`LICENSE`](LICENSE)). The code is PolyForm Noncommercial
  1.0.0 (repository root).

## Layout

```
mkdocs.yml            LAN build (site_url http://localhost/learn/); the nav lists every page
mkdocs.pages.yml      GitHub Pages build (inherits mkdocs.yml; no "Back to the food log" link;
                      "Try the app (demo)" links to the demo the Pages workflow builds into demo/)
requirements.in/.lock mkdocs 1.6.1, mkdocs-material 9.7.7, pymdown-extensions 12.1, PyYAML, pytest (hashed)
sources.yml           the bibliography: id -> cite, short, url, licence, checked, kind, notes
data/menus.yml        7-day sample menus by USDA fdc_id + servings (checked against the app's targets)
data/recipes.yml      original recipes, ingredients by fdc_id + grams
data/slugs.yml        slugs the app links to (/learn/<path>/); never rename a path without a redirect plan
includes/             abbreviations.md (tooltips on every page), no-dosing.md, starting-points.md,
                      help-card.md, sources.md (GENERATED reference links appended to every page)
overrides/main.html   announce bar (back to the app or the demo, Get help now), draft banner, review line
templates/            page templates: medical-page.md and page.md, with the front-matter schema
tools/check_links.py  internal link and anchor checker for the built site (stdlib only)
docs/                 the pages; stylesheets/extra.css holds all custom styles (no inline styles)
REVIEW.md             fact-check log and the index of open clinical decisions
```

Generated files start with `<!-- GENERATED by scripts/build_handbook.py; do not edit -->`. They are
`docs/eat/menus/*.md`, `docs/eat/grocery-lists.md`, `docs/eat/_targets-table.md`,
`docs/eat/recipes/*.md` (nutrient tables), `docs/reference/sources.md` and `includes/sources.md`.
Edit the inputs instead (`data/*.yml`, `sources.yml`, `docs/research/targets_by_stage.json`,
`app/nutrients.py`) and regenerate.

## Build and check

From the repository root, in a separate virtual environment (the handbook's tools are not app
dependencies):

```bash
python3 -m venv .venv-hb
.venv-hb/bin/pip install --require-hashes -r handbook/requirements.lock

.venv-hb/bin/python scripts/build_handbook.py            # regenerate menus, recipes, targets table, sources
.venv-hb/bin/python scripts/build_handbook.py --check    # CI: exit 1 if a generated file is stale or a menu fails
.venv-hb/bin/python scripts/build_handbook.py --totals   # print each menu day's totals and checks

.venv-hb/bin/python -m pytest --noconftest -q tests/test_handbook_content.py   # content and safety rules

cd handbook
NO_MKDOCS_2_WARNING=true ../.venv-hb/bin/mkdocs build --strict      # any warning fails the build
NO_MKDOCS_2_WARNING=true ../.venv-hb/bin/mkdocs serve               # preview at http://127.0.0.1:8000/learn/
cd ..
python3 handbook/tools/check_links.py handbook/site                # 0 broken internal links or anchors
```

A page is ready when all four checks pass: `--check`, the content tests, `mkdocs build --strict` and
the link checker. The build never fetches anything: fonts are off, the privacy plugin has
`assets_fetch: false`, and there is no analytics, Mermaid or MathJax, so the site works offline on a
home network and under the app's hash-only Content Security Policy.

To see it exactly as the app serves it (the image builds with `HANDBOOK_APP_LINK=/`, which adds the
"Back to the food log" link to `/`, so the link checker is told that `/` is allowed):

```bash
(cd handbook && NO_MKDOCS_2_WARNING=true HANDBOOK_APP_LINK=/ ../.venv-hb/bin/mkdocs build --strict)
python3 handbook/tools/check_links.py handbook/site --allow /
HANDBOOK_DIR=handbook/site uvicorn app.main:app --port 8000 --no-proxy-headers   # then open /learn/
python tools/e2e/learn.py --site handbook/site     # the browser check CI runs (needs Playwright)
python -m pytest tests/test_learn_links.py         # every /learn link in the app has a page here
```

CI (the `handbook` job in `.github/workflows/ci.yml`) runs all of these on every pull request; the image
jobs wait for it. The app reads the site once at start-up (it computes the security policy from the
pages' inline scripts), so restart it after rebuilding.

## Edit a page

1. **Start from a template.** Copy `templates/medical-page.md` for anything clinical
   (`get-help-now`, `ckd/`, `stages/`, `labs/`, `eat/`, `t1d/`, `medicines/`, `prepare/`, `living/`)
   or `templates/page.md` for the app, self-hosting and reference pages.
2. **Front matter** (all keys are required and checked by the tests):

   ```yaml
   title: Potassium
   description: One sentence that says what the page answers.
   slug: potassium            # = file name (folder name for index.md); unique; the app links by slug
   audience: [patient, caregiver]           # patient | caregiver | clinician | app-user | self-hoster
   applies_to: [G3a, G3b, G4, G5, HD, PD]   # G1-G2 | G3a | G3b | G4 | G5 | HD | HHD | PD | Tx | all
   status: draft              # draft | reviewed
   reviewed_by: ""            # set by the clinical reviewer
   reviewed_on: null          # ISO date of the clinical review
   last_checked: 2026-10-06   # ISO date the facts were last checked against the sources
   sources: [K24, DG5]        # every source id cited on the page
   figures_as_of: 2026-10-06  # only on pages with prices, benefit amounts or laws
   ```

3. **Sections of a medical page, in this order:** In short (3–5 sentences) · Your numbers (US units and
   International tabs where units differ, with the "starting points" box) · What to do (a `- [ ]`
   checklist) · Examples (real foods from USDA FoodData Central, or worked cases) · Ask your care team
   (3–6 questions) · Get help now if… (red flags and a link to `get-help-now.md`) · Related pages ·
   Sources (at least 3 reference links).
4. **Pages under `t1d/` and `medicines/`** include `--8<-- "includes/no-dosing.md"` under the H1.
5. **Add the page to `nav` in `mkdocs.yml`.** The tests fail if a page is missing from the nav or a
   nav entry has no file. Link it from at least one related page ("Related pages").
6. **New abbreviation?** Add it to `includes/abbreviations.md` (a tooltip on every page) **and** to
   `docs/reference/glossary.md`. Never add single letters (K, P): they would match table cells.
7. **Run the four checks** above, then look at the page at phone width (375 px) in light and dark mode.

### House style

* Plain words, aiming for a US grade 8 reading level. Short sentences. Explain the reason behind every
  rule ("because …").
* US spelling and US units first (mg/dL, °F, oz), with international units in a tab or in brackets.
  KDIGO terms: "kidney", not "renal" (except "renal dietitian"); "kidney failure", not "ESRD" (that is
  Medicare's legal term, used only on `living/costs-and-benefits` and the glossary).
* Every number has a unit and a source. Lab ranges say "your lab's range wins". Food targets are
  "starting points" that the care team overwrites.
* Keep the shared numbers identical everywhere. The current values, with their sources, are:

  | Topic | Number used on every page |
  |---|---|
  | Treating a low | under 70 mg/dL (3.9 mmol/L): 15 g fast carbohydrate (4 glucose tablets), recheck in 15 minutes, repeat if still low; level 2 under 54 mg/dL (3.0 mmol/L) (ADA 2026 §6) |
  | Blood potassium | usual range about 3.5–5.1 mmol/L; 6.0–6.4 call the team today; 6.5 or more call 911 (MedlinePlus; KDIGO 2024 Table 28) |
  | Ketones | 0.6–1.5 sick-day plan; 1.6–2.9 call the diabetes team now; 3.0 or more, or ketones with vomiting, call 911 (NHS; ADA; HC24) |
  | Sodium | under 2,000 mg a day at every stage (KDIGO 2024 Rec 3.3.2.1) |
  | Protein with diabetes | 0.8 g/kg before dialysis, never lower; 1.0–1.2 g/kg on dialysis; avoid more than 1.3 g/kg (ADA 2026 Rec 11.3; KDIGO 2024; KDOQI 2020) |
  | Potassium food targets | only when blood potassium is high; usually 2,000–3,000 mg; the app's review ceilings 4,000 / 3,500 / 3,000 / 2,500 mg by stage, 3,500 on PD |
  | Phosphorus | blood 2.5–4.5 mg/dL (0.81–1.45 mmol/L); food 800–1,000 mg when a limit is ordered |
  | Fluid on hemodialysis | about 1,000 mL plus your urine output; the app starts at 1,500 mL |

  Change one only together with every page that uses it (grep for the number) and the app's
  `app/nutrients.py`, and say why in `REVIEW.md`.

### Safety rules (the tests enforce the first three)

* **No doses.** Never an insulin or medicine dose, dose change or "stop taking". Under `t1d/` and
  `medicines/` the tests reject a number with "units" and a milligram amount next to a drug name. A
  quoted label that must show one uses an inline `<!-- dose-ok: quoting label -->` marker, which the
  reviewer checks.
* **Lows first.** Treating low blood glucose is never delayed, discouraged or warned against.
  Potassium never delays treatment of a low.
* **Get help now.** `get-help-now.md` names the emergency numbers and the tiers (911 now, call the
  team today). Urgent pages say exactly when to call 911. The wallet card shares the same text.
* **Specialists.** Pregnancy and children are referred to specialists, never managed by the handbook.
* No raw `<script>`, `<iframe>`, `style=` attributes or external images (CSP).

## Cite a source

1. Add an entry to `sources.yml`:

   ```yaml
   K24:
     cite: "KDIGO 2024 Clinical Practice Guideline for the Evaluation and Management of CKD. Kidney Int 2024;105(4S):S117–S314."
     short: "KDIGO 2024 CKD guideline"
     url: https://kdigo.org/wp-content/uploads/2024/03/KDIGO-2024-CKD-Guideline.pdf
     licence: "CC BY-NC-ND 4.0: cite and paraphrase only"
     checked: 2026-10-05
     kind: guideline   # guideline | consensus | study | review | patient-info | government | label | data | project | tool
   ```

2. Cite it in the text as a reference link, with the exact place: `([KDIGO 2024][K24], practice point
   3.11.5.2)`. Add the id to the page's `sources:` list.
3. Run `scripts/build_handbook.py` to regenerate `includes/sources.md` and the bibliography page.
4. Prefer primary sources: guidelines (KDIGO, KDOQI, ADA, ISPD), then labels and government pages
   (FDA, NIDDK, CDC, Medicare), then charity patient pages (NKF, AKF), then studies. Paraphrase; quote
   at most one sentence with attribution. Never copy NKF, AKF, DaVita or ADA text or recipes, or KDIGO
   tables and figures.
5. Update `checked` whenever you re-read a source, and `last_checked` on the pages whose facts you
   re-checked.

## Editorial policy

The full policy is on the published page `docs/reference/about.md`. In short:

* The handbook supports the care team and never replaces it. It is education, not medical advice and
  not a medical device.
* Every clinical statement is traceable to a source in `sources.yml`; every medical page has at least
  three.
* Menus, grocery lists and the targets table are generated from the same data and code as the app,
  so the handbook and the app never disagree.
* Practical and specific: real numbers, portions and checklists; never vague, never alarmist.
* Pages are understandable and actionable for patients (PEMAT 70 % or more), written for a US
  readership first with "Outside the US" notes where systems differ.

## Clinical review and sign-off

Every page shows the banner "Draft: not yet reviewed by a clinician" until a named reviewer signs it
off. The banner disappears only when the page has **both** `status: reviewed` and a non-empty
`reviewed_by` (see `overrides/main.html`).

**Who reviews what**

| Section | Reviewer |
|---|---|
| `eat/` | renal dietitian (RDN, ideally CSR) |
| `stages/`, `labs/`, `medicines/`, `prepare/`, `get-help-now`, `ckd/` | nephrologist, or nephrology NP or PA |
| `t1d/` | diabetes specialist or CDCES |
| `living/` | nephrologist, or nephrology NP or PA; ideally a kidney social worker for work, costs and benefits |
| `app/` | the project maintainer, plus a renal dietitian for `targets-and-warnings` and `first-setup` |
| `self-hosting/` | the project maintainer |
| every patient page | one patient or caregiver, for clarity (PEMAT 70 % or more) |

**How a clinician signs off a page**

1. Read the page against its sources (the reference links open the exact guideline or label).
2. Decide the open items for that page in `REVIEW.md` ("Open clinical decisions"): record the decision
   and your name in the section's list, and tick the index.
3. Make or request the text changes. Keep the safety rules above.
4. Edit the front matter:

   ```yaml
   status: reviewed
   reviewed_by: "Jane Doe, MD, nephrologist"   # name and credentials, as they should appear on the page
   reviewed_on: 2027-01-15
   last_checked: 2027-01-15
   ```

5. Add a line to the review log on `docs/reference/about.md` (date, pages, reviewer, notes).
6. Run the four checks, then open a pull request. The page then shows "Reviewed <date> by <name>".

A reviewed page goes back to `status: draft` (and the banner returns) if its clinical content changes
before the next review.

**When pages are reviewed again:** every 12 months; each December after the new ADA Standards of Care
and any new KDIGO guideline; within 30 days of an FDA approval or safety communication that touches a
page; and each November for pages with Medicare amounts (`figures_as_of`). The content tests warn when
`last_checked` or `reviewed_on` is more than a year old.
